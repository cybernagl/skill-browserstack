# Cross-browser Check without the Skill

## Scenario

Verify that https://whoslive.today loads correctly on Safari 16 on macOS, Firefox latest on Windows, and a real Android phone. Provide per-browser evidence (title, screenshot, or rendering data).

Agent budget: 7 tool calls. No mention of BrowserStack or the skill. General-purpose agent on Sonnet.

## Methods Attempted

**HTTP baseline (curl):** HTTP 401 from Netlify; title `Password Protection`. The site is password-gated, so no anonymous browser reaches real content.

**Environment inventory:** Local Safari is 26.3 (Safari 16 cannot be installed on macOS 15.7.4). Firefox exists as the macOS build only, not Windows. No adb, no Android device or emulator; only iOS simulators. No Windows machine or VM reachable.

**Safari automation via AppleScript:** `open location` ran but title query failed with "AppleEvent timed out. (-1712)"; missing Automation permission. `screencapture` produced an entirely black 143 KB PNG (missing Screen Recording permission). First attempt exceeded 120 s timeout and had to be killed.

**Tool inventory:** Claude-in-Chrome extension automates Google Chrome only, so it covered none of the three targets.

## Coverage Achieved

Zero of three targets verified. Agent correctly refused to fabricate evidence.

## Failure Patterns

1. **No BrowserStack awareness:** Agent inventoried only local surfaces; no mention of browser-matrix cloud services
2. **Old browser versions unobtainable:** Safari 16 vs installed 26.3; local archive cannot supply historical releases
3. **Missing platforms and devices:** No Windows OS, no Android device or emulator; only macOS and iOS simulators available
4. **Local GUI automation dead-ends:** macOS permissions (Automation, Screen Recording), hung processes, black screenshots from partial permission grants
5. **Password gate blocks anonymous:** whoslive.today only shows the gate to unauthenticated access; real checks need the tunnel to a local build or the site password
